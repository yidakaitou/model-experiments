# 03 · 带信念的 agent：记忆如何替代权重

## 问题

一个长期陪伴的 agent 需要"记得住"，但权重不能天天重训。所以记忆必须外挂。

外挂记忆真正难的不是"存下来"，是**三个"人会觉得假"的地方**：

1. **人会变**（"我搬家了"）——旧值不能直接删掉，得能追溯
2. **信息有可信度差异**（她随口说的 vs 反复确认的）
3. **数据会被污染**（一次错误的记忆会让她后面的话全变味）

## 设计

### 1. 信念库：失效而不覆盖

每条记忆带三个时间字段：

```python
Node(slot="住处", value="成都",
     valid_from=..., valid_to=None,      # 何时生效、何时失效
     supersedes="a1b2c3",                # 取代了哪条
     status="active")
```

同一个槽位出现新值时：
- 旧的 `valid_to` 设为当前时间，`status = "superseded"` —— **不删除，保留可查**
- 新的记录 `supersedes = 旧条 id` —— **形成链条**

**关键修复**：最初实现是"命中第一条旧值就返回"，导致槽位变两次时（杭州 → 成都 → 西安），第二条永远不被作废。

**这个 bug 在 5 窗口的短测试里测不出来**——因为每个槽只变一次。**40 窗口的长程测试才暴露。**

### 2. 质量闸

不是所有东西都配进记忆。入库前做一道判断（是否有实质信息、是否重复、是否可信）。

否则记忆会膨胀，而且被噪音污染。

### 3. 变更日志

每次 `new / merged / superseded` 都落一条日志：`from → to`、原因、证据。

**好处是可审计**：能回答"你为什么认为她住在成都"——这个问题不可答的记忆系统是不可信的。

## 40 窗口长程测试

事实轨迹：

```
住处    杭州 →(W12) 成都 →(W28) 西安
工作    银行 →(W20) 设计公司
称呼    名字（不变）
恋爱    单身 →(W34) 有对象了
别人    W6/W15/W25 妈妈/朋友/同事说自己的事（不能进来）
```

结果：

| 检查 | 结果 |
|---|---|
| 最终状态正确 | ✅ 西安 / 设计公司 / 有对象了 / 名字 |
| 全部旧值已失效 | ✅ 杭州、成都、银行、单身 |
| **未混入他人事实** | ✅ |
| 记忆未膨胀（节点数） | ✅ 8 条（4 有效 + 4 失效） |

## 一个设计原则：分层负责

端到端测试里，有几个能力**故意没有交给模型**：

| 谁 | 负责什么 | 为什么 |
|---|---|---|
| **模型** | 判断该不该问、给候选（slot+guess）、抽取、撤回 | 需要语义理解 |
| **规则** | 理解"对/不是"这类短回答 | 形式有限，规则比模型可靠 |
| **代码** | 失效、取代、冲突 | 逻辑确定，代码比模型可靠 |

**起因**：模型在"嗯对"这种极简回答上失败（差一个逗号就从成功变失败）。

**结论不是"训练它学会所有确认词"，而是"这件事根本不该由模型做"。**

给模型加结构化输出（`slot` + `guess`），再由 20 行规则处理确认/否认——比指望模型泛化所有口语说法可靠得多。

## 局限

- 测试只有 40 个窗口、1 个场景、单次运行
- 没有测"用户反驳后记忆如何回滚"
- 没有真实长期使用数据
- 冲突检测是启发式的（相似度阈值），不是语义理解
