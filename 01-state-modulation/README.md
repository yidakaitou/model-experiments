# 01 · 内部状态参与计算（FiLM 调制）

## 问题

让模型的"状态"（情绪、疲惫度、亲密度）**真正参与判断**，而不是当一段附加文本拼进 prompt。

为什么要区分这两件事：如果状态只是拼在输入里，模型可以完全忽略它——**"影响了输出"和"带来了收益"是两件事**。

## 设计

四组对照，同一个任务、同一份数据、同样的训练步数：

| 组 | 状态怎么进去 | 作用 |
|---|---|---|
| `text` | 完全没有状态 | 下界 |
| `state` | 单独输入状态（非文本） | 测"状态本身有没有信息" |
| `concat` | 状态向量拼接到隐层 | 最直觉的做法 |
| **`film`** | **`h ← (1+γ(s))·h + β(s)`，每层调制** | 乘性调制 |

任务用 XOR-like 构造：**正确答案同时依赖文本和状态，且状态提供的信息不在文本里**。这样"忽略状态"一定会掉分。

## 结果（bert-base 110M，3 个随机种子）

| 组 | 准确率 | 标准差 |
|---|---|---|
| text | 0.4957 | 0.0089 |
| state | 0.4935 | 0.0129 |
| concat | 0.4947 | 0.0091 |
| **FiLM** | **0.7860** | **0.0046** |

**FiLM 比拼接高 29 点，而且波动只有 0.46%。**

拼接组等于随机猜（0.4947 ≈ 0.5）——**这是最反直觉的一点：把状态拼进输入，和完全没有状态没区别。**

## 规模验证

| 规模 | FiLM 相对拼接 |
|---|---|
| 110M | +29.1 点 |
| 340M | **+30.0 点** |

**效应没有随规模衰减。**

## 真实任务

换成"个性化情绪判断"（同一个情绪词，不同的人含义不同），FiLM 比拼接高 **18.5 点**。

## 一个必须说清的代价

**门控学习率必须 ≥ 1e-2。**

一开始用 3e-4（和主干一样），FiLM 和拼接没有区别——**看起来像"机制无效"**。

原因是门控参数初始化接近 0（`(1+0)·h + 0 = h`），学习率太小的话，**门控永远打不开，模型等价于原模型**。

这个坑如果没测出来，结论就会写成"乘性调制没用"，而实际上是**优化器推不动门控**。

## 局限

- 任务规模小：110M/340M，不是大模型
- 任务是我自己构造的，不是真实业务场景
- 只验证了"状态影响分类判断"，**没有验证生成任务**（另一篇论文报告 FiLM 在语音生成上 WER 恶化到 53%）
