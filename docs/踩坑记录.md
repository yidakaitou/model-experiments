# 踩坑记录：四次"模型能力问题"其实都是数据问题

> 这份文档比任何指标数字都更能说明我的工作方式。
>
> 四次的共同结构：**现象看起来像模型不行 → 我先怀疑模型 → 最后都证明是我的数据/评测错了。**

---

## 坑 1：卡在 0.7，加 epoch 也没用

**现象**：抽取任务，fact_exact 稳定停在 0.70。训练 loss 掉到接近 0，验证集不动。

**第一反应**：模型太小了（当时是 1.7B），换 4B。→ **还是 0.70。**

**第二反应**：是不是数据不够？加样本到 3000 条。→ **还是 0.70。**

**真正的排查**：把预测逐条 dump 出来，跟标准答案并排对比。

发现 **24 条失败里 23 条是"同槽不同值"**：
```
标准答案：住处 = 城西（后来的说法）
模型输出：住处 = 杭州（更早的说法）
```

**根因**：我的数据生成器把同一段对话里的多行**打乱了顺序**（shuffle）。任务要求是"以最后一次说法为准"，但行被 shuffle 之后，**"最后一次"在文本里不可判定**。

**标签本身不可学**，模型当然学不到。

**修复**：事实行保持时间顺序。→ **0.70 → 1.00。**

**教训**：`训练 loss → 0 而验证不涨`，最可能是**标签错了**，不是模型容量不够。加数据/加 epoch 都是浪费。

---

## 坑 2：加了多人数据，"分清谁说的"能力纹丝不动

**现象**：模型在 `multispeaker` 留出集上只有 0.53——一半的"别人的话"被记成了用户的。

**第一反应**：训练集里没有多人对话，加进去。→ 造了 900 条含"妈妈说/朋友说"的数据。

**结果**：0.53 → **0.54**。几乎没动，而且 `long` 掉到 0.64。

**真正的排查**：把训练数据和测试数据里"别人怎么说话"直接摆在一起看：

```
训练数据：妈妈说：妈妈搬家了，现在住在西安     ← 第三人称
测试数据：朋友说：我最近在谈恋爱               ← 第一人称
```

**根因**：我的生成器把"别人"写成了第三人称（"妈妈搬家了"）。而真实对话里，别人说自己当然用"我"。

**模型学到的是表面捷径**："看第三人称主语是谁"。到了测试集，朋友说"我"，它分不清这个"我"是谁。

**修复**：别人也改成第一人称。→ **0.53 → 0.79。**

**另一部分**：`long` 掉 0.64 是因为加了别人的行之后，对话整体变长，**超出了训练时的长度分布**，JSON 开始退化。把闲聊行数拉宽到 2–10 行后恢复。

**教训**：训练和测试的**表面形式必须一致**。表现形式差一个"人"字，模型就学不到规则，只能学到捷径。

---

## 坑 3：上线后"什么都要抽"

**现象**：合成测试集 8B 做到接近满分。拿去跑 100 段真实对话，**86% 的窗口被强行抽出事实**。

**第一反应**：过拟合了？→ 但同分布测试集也是满分，如果过拟合早该崩。

**真正的排查**：看它抽出来什么：

```
真实对话：「呼 吸 呼 吸 呼吸」
模型输出：她的恋爱状态 = 被理解了
```

**它在"必须从每段话里找到点什么"**——因为训练集里每一条样本都至少有一个事实。

**它从没学过"这轮没有事实"这个动作。**

**修复**：加 30% 的"无事实窗口"（真实闲聊，gold = 空）。

**但有个陷阱**：如果只加"真实文本 → 空"，模型会学到"真实文风就闭嘴"。所以必须**混入"真实文本 + 插入一条事实"**，逼它看内容而不是看文风。

**验证**：往真实窗口里插入明确事实 → **0.99 能抽出来**；纯闲聊 → **100/100 正确输出空**。**证明它学到的是规则，不是文风捷径。**

**教训**：**训练分布必须覆盖"什么都不该做"的情况**。如果每个样本都有答案，模型就会永远给答案。

---

## 坑 4：加新能力，把旧能力挤掉了

**现象**：为了加"识别撤回/主动提问"能力，重新配了一版数据（4900 条，含撤回 900、含糊 700）重训 8B。

**结果**：新能力出现了，但**旧能力全面崩塌**：

| 指标 | 上一版 | 新一版 |
|---|---|---|
| 黑箱对抗 15 题 | 9 对 / 2 错 | **5 对 / 9 错** |
| 含糊输入硬抽率 | 0.117 | **0.783** |

**真正的排查**：对比两版数据的构成：

| | 旧版 | 新版 |
|---|---|---|
| 真实无事实（教"闭嘴"） | 1050 条 | **900 条** |
| 合成事实 | 1800 条 | **1200 条** |

**根因**：**加新类别但总样本量没扩，每个旧能力都被稀释了。** 比例一降，能力就掉。

这是灾难性遗忘在真实任务上的重演。

**教训**：**加新能力要靠"追加"，不能靠"重新配比"。** 旧数据一条不能少。

---

## 这四个坑的共同点

| 我以为是 | 实际是 |
|---|---|
| 模型容量不够 | 标签不可学 |
| 数据量不够 | 训练/测试形式不一致 |
| 过拟合 | 训练分布缺少"什么都不做"的样本 |
| 加新能力有代价 | 旧样本被稀释 |

**四次都不是模型的问题。**

所以我现在的工作顺序是：

```
1. 先 dump 逐条对比（预测 vs 标准答案）
2. 再看训练集和测试集的分布差异
3. 最后才怀疑模型
```

**这个顺序省下来的时间，比换模型省的多得多。**
