# 02 · 结构化抽取能力：让 8B 可靠地"记住她说的"

## 问题

让模型从对话里抽取稳定的事实，要求三条：

1. **只记用户本人说的话**（混入别人的话不能串台）
2. **同槽位取最后一次**（人会说"我搬家了"）
3. **拿不准时闭嘴**（不能编）

零样本时，8B 连合法 JSON 都出不来（`json_ok = 0.0`）。

## 做法

### 1. 自己构造数据

没有现成的"对话 → 结构化结论"数据集，所以从零写生成器。核心设计：

| 设计 | 为什么 |
|---|---|
| 事实行**保持时间顺序** | 否则"最后一次"不可判定（踩坑 1） |
| 别人说话**也用第一人称** | 否则模型学会看第三人称主语这个捷径（踩坑 2） |
| 对话长度**拉宽到 2–10 行** | 否则长输入超出分布，JSON 退化 |
| **30% 的"无事实窗口"** | 否则模型永远给答案，不会闭嘴（踩坑 3） |
| 混入"真实对话 + 插入事实" | 防止模型学到"真实文风就闭嘴"这个假规则 |

最终数据：4900 条，四类动作（记 / 闭嘴 / 撤回 / 提问）。

### 2. 五个泛化留出集

只报一个总分会掩盖问题，所以每个留出集考一个维度：

| 留出集 | 考什么 | 8B 结果 |
|---|---|---|
| `long` | 事实埋在 12 行闲聊里 | 1.00 |
| `noise` | 口语填充词（嗯/那个/对了） | 1.00 |
| `novel` | 训练集没见过的城市/公司名 | 1.00 |
| `paraphrase` | 换一种说法 | 0.98 |
| **`multispeaker`** | **混入别人的话** | **0.79 → 1.00**（见下） |

**`multispeaker` 是最先崩的一项（0.19）。** 它会把"朋友说我在腾讯上班"记成用户的。

### 3. 逐步修，每一步都验证

| 改动 | multispeaker | long |
|---|---|---|
| 基线（4B，无多人数据） | 0.53 | 0.91 |
| 加多人数据（别人用第三人称）**失败** | 0.54 | **0.64** |
| 改成第一人称 + 长度拉宽 | **0.79** | **1.00** |
| 换 8B | **1.00** | 1.00 |

### 4. 自检（模型审自己的输出）

给它一段对话 + 一条结论，问"这条能否从对话里得到支持"。

| 版本 | 编造方式 | 准确率 |
|---|---|---|
| 基础版 | 值**不在**原文里 | 0.98 |
| **归属版** | 值**在**原文里，但是别人说的 | **1.00（156 题，零误报零漏报）** |

**归属版是关键**：字符串匹配救不了"值在文内但归属错"，必须真判断谁说的。

## 一个失败的对照实验（A/B/C）

加"主动提问"能力时，我想知道**能不能靠联合训练消掉手写规则**：

| 组 | 输入格式 | 规则兜底 | 结果 |
|---|---|---|---|
| A | 整段对话 | 有 20 行确认词规则 | ✅ 通过 |
| B | 整段对话 | **无** | ❌ 失败（"嗯对"→输出空） |
| C | **显式标注 `[提问]`/`[回答]`** | **无** | ✅ **通过** |

**结论**：不是模型学不会，是**"这句话在回答哪个问题"这个信息没传进去**。

只改输入格式，失败变成功。**这说明拼装式系统的瓶颈在接口设计，不在模型能力。**

## 局限（重要）

- **所有评测数据都是我合成的。** 真实对话只测了 100 个窗口
- 大部分结论是**单次运行**，只有项目一做了 3 seeds
- 8B 是**单卡 LoRA（r=16）**，没有全参微调、没有多卡
- 训练集 4900 条，**不是百万级**
- 同分布 1.00 这个数字**不可信地漂亮**，真实场景会掉（实测真实对话上过度抽取率 86% → 修好后 0/100）
